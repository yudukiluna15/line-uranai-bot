# AI占い LINE公式アカウント ボット

生年月日から西洋占星術ベースの鑑定を行い、LINE公式アカウント上で
課金制の鑑定チャットを提供するサーバーです。

## 構成

```
app/
├── main.py            FastAPIエントリーポイント(Webhook受け口)
├── line_bot.py         LINEの会話フロー・返信ロジック
├── fortune_service.py  鑑定処理の中心(DB操作+AI呼び出しの橋渡し)
├── astrology.py        生年月日→星座の計算(kerykeion使用)
├── tarot.py             タロットカード抽選
├── ai_service.py        Claude APIへの鑑定文生成・要約リクエスト
├── payment.py            Stripe決済(チェックアウト発行・Webhook処理)
├── models.py             DBテーブル定義(User/ChatLog/Summary/Subscription)
├── database.py           DB接続設定
└── config.py             環境変数の読み込み
```

## セットアップ

```bash
# 1. 依存パッケージのインストール
pip install -r requirements.txt

# 2. 環境変数を設定
cp .env.example .env
# .env を開いて各種キーを入力

# 3. ローカルで起動
uvicorn app.main:app --reload
```

## 必要な外部サービスの準備

1. **LINE Developers**
   - Messaging APIチャネルを作成
   - チャネルシークレット・チャネルアクセストークンを`.env`に設定
   - Webhook URLに `https://<デプロイ先ドメイン>/webhook/line` を登録

2. **Anthropic Console**
   - APIキーを発行し`ANTHROPIC_API_KEY`に設定

3. **Stripe**
   - 商品(月額サブスクリプション)を**スタンダード・プレミアムの2つ**作成し、
     それぞれのPrice IDを`STRIPE_PRICE_ID_STANDARD`・`STRIPE_PRICE_ID_PREMIUM`に設定
   - Webhookエンドポイントに `https://<デプロイ先ドメイン>/webhook/stripe` を登録し、
     以下のイベントを購読:
     - `checkout.session.completed`
     - `customer.subscription.updated`
     - `customer.subscription.deleted`
   - Webhook署名シークレットを`STRIPE_WEBHOOK_SECRET`に設定

## デプロイ

Render / Railway / Fly.io など、Pythonが動く任意のPaaSにデプロイできます。
SQLiteはファイルベースのため、複数インスタンスでの運用や永続化を
本格的に行う場合はPostgreSQLへの切り替え(`DATABASE_URL`の変更のみ)を推奨します。

## 会話フロー概要

1. 友だち追加 → ルナ・玄が挨拶し、生年月日を尋ねる
2. (任意)生まれた時間・場所を尋ねる(不明なら「スキップ」)
3. カテゴリ選択(恋愛運/仕事運/金運/健康運/総合運/相性診断)のクイックリプライを表示
   → 選択するとそのまま鑑定文を生成する(悩み相談機能は持たず、受け身型の
   運勢鑑定のみを提供する方針。カテゴリ・ボタン以外の自由な文章を送ると、
   メニューから選ぶよう案内するだけで鑑定はしない)
4. プランごとに使えるカテゴリ・相性診断の月間回数が異なる(下記「プラン設計」参照)
5. 「プラン確認」→「スタンダード登録」「プレミアム登録」を選ぶとStripeの
   チェックアウトURLを送信(初月無料トライアル設定済み)
6. 鑑定文は「ルナ(優しい語り)」→「玄(断定的な一言)」の2つの吹き出しに分けて送信
   (LINEの`sender`機能でメッセージごとに名前・アイコンを切り替えている。
   reply=返信は何通送っても追加費用がかからないため、手動操作への
   返信はこの2通形式のままにしている)
   ※鑑定文だけでなく、案内・エラーメッセージもすべてこの掛け合い口調で統一している
7. 総合運の後は「今日の1枚」ボタンで、その日引いたタロットカードの画像を見られる
   (`TAROT_IMAGE_BASE_URL`未設定の間はテキストでカード名を返すだけ)
8. 鑑定文の下に「当たってた/ちがった」のフィードバックボタンを表示 →
   反応をDBに記録し、同じカテゴリで「ちがった」が続くとAIへ表現を
   見直すヒントとして渡される(`fortune_service.get_reaction_hint`)
9. 会話ログが一定件数(`SUMMARY_THRESHOLD`)たまるとAIが自動要約し、
   次回以降の鑑定プロンプトに差し込まれる(相談内容ではなく、運勢の
   推移・伝えた予兆を中心にした要約)

## プラン設計

| プラン | 月額 | 使えるカテゴリ | 相性診断(月間) | 記憶機能 | 毎日自動配信 |
|---|---|---|---|---|---|
| 無料 | ¥0 | 総合運のみ、1日`FREE_DAILY_LIMIT`回まで | 1回 | なし | なし |
| スタンダード | Stripe側で設定 | 総合運・恋愛運・仕事運 | 5回 | あり | あり |
| プレミアム | Stripe側で設定 | 総合運・恋愛運・仕事運・金運・健康運 | 15回 | あり | あり |

- カテゴリ・相性診断の上限は`app/line_bot.py`の`PLAN_CATEGORIES`・
  `COMPATIBILITY_MONTHLY_LIMIT`で定義している(変更はここを編集するだけでよい)
- どのプランでも、相性診断以外の各カテゴリは1日1回に制限される
  (`fortune_service.get_todays_cached_fortune`。同じ日に見るたびに
  内容が食い違うのを防ぐため)
- Stripeの支払い状況(`Subscription.status`)がactive/trialingでない場合は、
  登録したプランに関わらず無料扱いになる(`line_bot.get_user_plan`)

## 占い師・占いコンサルタント視点での追加対策

- **引いたカードの記録**:総合運で引いたタロットカードは、`ChatLog.tarot_card`/
  `tarot_orientation`にカテゴリと一緒に保存される。「今日の1枚」ボタン
  (`fortune_service.get_todays_tarot_card`)や、将来の「タロット図鑑」
  機能(`fortune_service.get_drawn_card_names`)にそのまま使える
- **カテゴリ横断の一貫性**:総合運と各カテゴリ(恋愛運・仕事運など)を
  同じ日に両方見た場合、正反対の運勢の方向性(片方は絶好調、もう片方は
  動くな、など)にならないよう、当日すでに生成済みの他カテゴリの結果を
  次の生成時にAIへ一緒に渡している(`fortune_service.
  get_todays_other_categories`)。完全に同じ内容にする必要はなく、
  矛盾さえ避ければ良い、という緩やかな整合性を意図している
- **ラッキーアイテム/カラー**:総合運には、タロットや星座の解説だけでなく、
  具体的なラッキーアイテムとラッキーカラーを1つずつ自然に含めるよう
  `CATEGORY_ELEMENTS["総合"]`で指示している
- **恋愛運・仕事運にも今日の月の動きを反映**:固定値(生まれた日で決まる
  星座情報)だけでなく、「今日という日だからこそ」の要素が入るよう、
  今日の月の動きも軽く絡めるよう指示している
- **同じ日の一貫性**:同じ日に同じカテゴリを複数回見ても、内容が
  食い違わないよう当日分をキャッシュして使い回す(相性診断は相手が
  毎回変わるため対象外で、月間回数での制限に切り替えている)
- **ルナと玄の矛盾防止**:玄のセリフがルナの助言と逆のことを
  言わないよう、SYSTEM_PROMPTで明示的に禁止している
- **不吉なタロットカードへの配慮**:死神・塔・悪魔などのカードには
  「前向きな伝え方」の注記を`tarot.py`に用意し、いたずらに不安を
  煽らないようにしている
- **相性診断で相手の名前を使う**:生年月日だけでなく名前も尋ね、
  「〇〇さんとの相性は」と語りかける
- **深刻な相談へのセーフティネット**:自傷・自殺などのサインを
  検知した場合、占いとして処理せず相談窓口の案内に切り替える
  (`CRISIS_KEYWORDS`は簡易的なキーワード検知のため、検知漏れ・
  誤検知はありうる前提で、本番運用前に精度を検証すること。
  電話番号も変更される可能性があるため、掲載前に必ず最新情報を確認する)
- **悩み相談機能は持たない**:会話が続く相談形式は、深刻な内容への
  対応リスク・法律や医療相談との境界の際どさ・コストの見積もりにくさから
  見送り、受け身型の運勢鑑定のみに絞っている(意図的な設計判断)

## タロットカード画像の設定(準備でき次第)

`.env`の`TAROT_IMAGE_BASE_URL`にカード画像を置いた場所のベースURLを
設定すると、「今日の1枚」ボタンで画像が送られるようになります。

- 画像ファイル名は、`tarot.py`の`MAJOR_ARCANA`の並び順に対応する
  **2桁の連番**を想定しています(`00.jpg`=愚者 〜 `21.jpg`=世界)。
  日本語ファイル名は環境によって文字化けしやすいため、あえて連番にしています
- 画像はHTTPS上に公開されている必要があります(GitHubのraw URL、
  Cloudflare R2、AWS S3など)
- 未設定のままでも動作します(その場合はカード名をテキストで返すだけ)
- 総合運の自動配信(push)には画像を含めていません(通数課金が増えるため)。
  画像は「今日の1枚」ボタン経由のreply(無料)でのみ送信されます

## キャラクターアイコンの設定

`.env`の`LUNA_ICON_URL`・`GEN_ICON_URL`に、それぞれのアイコン画像のURLを
設定すると、LINE上でルナ・玄それぞれの名前とアイコンでメッセージが表示されます。

- 画像はHTTPS上に公開されている必要があります(GitHubのraw URL、
  Cloudflare R2、AWS S3など)
- 正方形のPNG/JPEG画像を推奨(LINEの表示上、円形にトリミングされます)
- 未設定のままだと、通常通り公式アカウント名で送信されます
- `linebot`(line-bot-sdk)のバージョンによっては`Sender`クラスが
  古い場合があります。`from linebot.models import Sender`で
  ImportErrorが出る場合は、`pip install -U line-bot-sdk`で
  最新版に上げてください(ただしrequirements.txtでは動作確認済みの
  2.4.2を固定指定しているため、上げる場合は他の挙動も併せて確認してください)

## 有料会員への毎日自動配信

`DAILY_PUSH_ENABLED=true`(デフォルト)の場合、毎日`DAILY_PUSH_HOUR:DAILY_PUSH_MINUTE`
(日本時間)に、有料会員(`Subscription.status`が`active`または`trialing`)
全員へ「総合運」の鑑定文を自動でpush配信します。

- 仕組みはアプリ内蔵のAPScheduler(`app/main.py`起動時に開始)で完結しており、
  デプロイ先で別途Cronを設定する必要はありません
- ただし、アプリのプロセスが再起動した際にスケジュールも作り直されるため、
  頻繁に再起動がかかるようなホスティング環境では配信が飛ぶ可能性があります。
  安定運用したい場合は、デプロイ先のCron機能を使う方式への切り替えも検討してください
- 1人ずつ星座が異なるため、全員同じ内容を送るのではなく**ユーザーごとに
  個別に鑑定文を生成してpush送信**します。そのため有料会員の人数分だけ、
  毎日AI APIの呼び出しが発生します(コスト試算の際にご注意ください)
- LINEの配信通数は「吹き出しの数」でカウントされ、push messageは通数分の
  課金対象になるため、**ここではルナ・玄を1通にまとめて送信**しています
  (`line_bot.build_combined_message`。手動操作への返信は無料のため、
  そちらは引き続き2通のまま)
- 無料ユーザーには配信されません
- `DAILY_PUSH_ENABLED=false`にすると自動配信自体を止められます

## 現状の実装範囲と今後の拡張ポイント

- **時間帯・場所の都市名解決**:`birth_place`は都市名の文字列をそのまま
  kerykeionに渡しています。日本語都市名など解決できない入力があると
  太陽星座のみのフォールバック計算になります。
- **タロットカード画像**:22枚分の画像そのものはまだ用意されていません。
  用意でき次第、上記「タロットカード画像の設定」の手順でURLを設定するだけで
  使えるようになります。
- **既存DBとの互換性**:今回のプラン別制限・タロット記録の追加に伴い、
  `ChatLog`にカラムを追加しています。すでに動かしたことのあるSQLite
  ファイル(`uranai.db`)がある場合は削除して作り直してください。
- **管理画面**:問い合わせ対応やAI出力のモニタリング用の管理画面は未実装です。
- **実機テスト未実施**:LINE DevelopersでのWebhook接続・Stripe決済の
  実際のテストはまだ行っていません。ローカルでの鑑定文生成テストまでの確認です。
